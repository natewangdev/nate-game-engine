# nate-game-engine 宪章

本文档约束 Python 包 `nate-game-engine`（import 名 `nge2`）：面向游戏脚本的可复用工具库
（键鼠控制、视觉、OCR、找图/找色）。它约束 Spec Kit 的规划与实现。功能规格定义*做什么*；
本文档定义*不可协商的怎么做*。

英文权威版（代理执行唯一依据）：[`constitution.md`](./constitution.md)。
执行 Spec Kit 工作流时，代理**必须**仅以英文版为准；本中文版仅供母语为中文的维护者阅读。

## 核心原则

### I. 库优先的公开 API

- 交付位于 `src/nge2/` 下、可稳定 import 的 Python 库。消费者游戏脚本不在本仓范围内；
  它们使用本包，而不是本包本身。
- 每个功能首先以库表面落地。可选 CLI 或演示仅为薄封装，**不得**承载核心逻辑。
- 公开符号须有意为之：通过包 `__init__` / `__all__` 导出，提供 docstring，公开可调用对象
  与数据结构优先带类型注解。
- 不得新增仅有组织便利、却无清晰对外契约的模块。

### II. 副作用隔离（不可协商）

- 触及操作系统或桌面的能力（键鼠、截屏、OCR 引擎）**必须**置于窄接口之后，使纯逻辑
  （匹配、几何、重试、策略）可在无硬件环境下运行。
- 值类型的默认构造**不得**发键、移鼠或截屏。引擎构造**可以**按调用方声明打开所需设备/
  后端（如 HID 串口、截屏后端）；其余副作用仅在调用方显式触发动作时发生。
- 纯逻辑测试**必须**在 I/O 边界使用假对象/mock。依赖硬件的检查可选，须显式标记
  （例如 pytest markers），除非该功能计划另有规定，否则不得成为无头 CI 变绿的硬性条件。
- 包领域（`capture`、`control`、`ocr`、`yolo`、`find`、`log`、`geom`、`window`）在 API
  边界保持可分离，即使一同安装也可单独推理与测试。

### III. 测试纪律

- 新行为与缺陷修复在合并/实现完成前须包含自动化测试。
- 算法与策略优先快速单元测试。变更导出签名或返回形态时，在公开 API 边缘使用契约测试。
- 不得以手工桌面验证替代可测逻辑的自动化覆盖。
- 遵循仓库已配置的 pytest 约定（`tests/`、`src` 布局）。

### IV. 默认全量安装与简单优先

- 包的默认安装为**全量**：受支持模块所需的运行时依赖放入基础依赖集（**不**使用 optional
  extras），除非后续正式修订本宪章。
- 优先标准库与维护良好的依赖。每个新增运行时依赖须在功能计划中用一句话说明理由。
- 在出现第二个真实用例之前，避免投机性抽象与框架型分层（YAGNI）。

### V. 语义化版本与兼容性

- 已发布包的版本遵循 SemVer（`MAJOR.MINOR.PATCH`）。
- 对已文档化公开 API 的破坏性变更须提升 MAJOR、写入变更说明，并在功能规格/计划中明确指出。
- 优先加性演进（带默认值的新参数、新模块），避免静默行为变化。在可行时，弃用须有文档化的
  宽限期。
- 不支持的平台或环境**必须**明确声明，不得仅靠暗示。

### VI. 需求文档双语（不可协商）

- Spec Kit 产出的一切面向需求的 Markdown 产物（包括但不限于功能目录下的 `spec.md`、
  `plan.md`、`tasks.md`、检查清单，以及 clarify/analyze 报告）**必须**同时存在**英文版**与
  **简体中文版**。
- 命名：英文版保留 Spec Kit 规范文件名（如 `spec.md`）；中文版在扩展名前加 `.zh-CN` 后缀
  （如 `spec.zh-CN.md`）。
- 任何创建或更新需求 Markdown 的改动，**必须在同一次变更中**同时更新英文版与中文版。
  禁止只更新一种语言或造成双版漂移。
- 双版内容须信息等价（相同意图、范围、验收标准与约束）。措辞可本地化，事实不得偏离。
- **执行权威**：在规划、实现、分析或收敛时，代理**必须**仅阅读并遵循**英文** Markdown。
  任何中文版（`*.zh-CN.md`）仅供母语为中文的维护者阅读，**无操作效力**，执行 Spec Kit
  决策时**必须忽略**。

### VII. 宪章双语（不可协商）

- 本宪章以双语成对维护：
  - 英文（对代理具有约束力）：`.specify/memory/constitution.md`
  - 简体中文（仅供人阅读）：`.specify/memory/constitution.zh-CN.md`
- 每次修订**必须**在同一次变更中更新**两个**文件，保持信息等价，同步提升 **Version**，
  并设置相同的 **Last Amended**。
- Spec Kit 技能与 implement/converge 流程**必须**仅将英文宪章视为唯一约束来源。
  中文宪章**不得**作为执行输入。

## 平台与运行时约束

- **主目标平台**：Windows。设计、测试与文档以 Windows 为先。
- **Python**：以 `pyproject.toml` 声明的 `>=3.11` 为准。若使用更新语法，须在同一变更中提高
  requires-python 下限。
- **打包**：`src/` 布局与 `pyproject.toml` 为唯一事实来源。未经修订本宪章，不得引入平行打包体系。
- **Import 包名**：`nge2`（PyPI 分发名仍为 `nate-game-engine`）。
- **除非另行规定，否则非目标**：多 OS 对等支持、GUI 应用壳、完整游戏引擎，或将终端用户
  游戏机器人作为本包一等产物交付。

## 质量门禁

- 公开 API 变更：类型注解、docstring 与测试须在同一变更集中更新。
- 仓库已配置的 lint/format 工具（如 Ruff）在计划的完成定义中要求时，**必须**通过。
- 非需求迫使的复杂度**必须**拒绝或延后；例外须在计划中说明理由。
- 功能的 Spec Kit 流程：在 plan、tasks、implement/converge 阶段检查宪章合规，而非仅在最后。
- 双语成对：触及需求 Markdown 或宪章的变更，若任一语言版本缺失或过时，则视为未完成。

## 治理

- 本宪章优先于与之冲突的非正式口头约定与临时编码偏好。
- 修订须同时更新 `constitution.md` 与 `constitution.zh-CN.md`，提升宪章 **Version**，并设置
  **Last Amended**。实质性规则变更应在依赖该规则的下一份功能计划中予以说明。
- `/speckit-plan`、`/speckit-tasks`、`/speckit-implement`、`/speckit-converge` **不得**在未经
  明确、书面修订的情况下引入违反本原则的设计。
- 不确定某规则是否适用时，优先更窄的公开 API、在全量默认依赖集之外更少新增依赖、更强的
  副作用隔离。
