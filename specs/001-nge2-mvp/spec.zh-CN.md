## 澄清记录

### Session 2026-09-26

- Q: `capture.release()` 释放后端后，同一引擎上后续 `grab()` 应如何？ → A: 后续 `grab()` 自动重建同一截屏后端并成功截屏（选项 A）。
- Q: `NGE2` 是否必须提供显式关闭以释放 HID 串口与截屏？ → A: 必须提供 `close()`，并支持上下文管理器（`with`）；退出时释放本实例 HID 与 capture（选项 A）。
- Q: 若构造时所选截屏后端无法创建，应如何？ → A: 构造立即失败并明确报错；不自动回退到另一后端（选项 A）。
- Q: MVP 中 `ocr`/`yolo` 是否以可 import 空壳存在？ → A: MVP 包内提供可 import 的 `ocr`/`yolo` 空壳；调用能力 API 时抛 `NotImplementedError`（与 `find` 一致）（选项 A）。
- Q: 若已有 `NGE2` 占用 ESP32-S3 串口，第二实例以 `control_mode=2` 构造应如何？ → A: 第二实例构造立即失败，并给出端口/设备忙的明确可操作错误（选项 A）。

## 用户场景与测试 *(必填)*

### 用户故事 1 - 构造引擎并截屏（优先级：P1）

脚本作者创建 `nge2.NGE2` 引擎（必填资源目录、可选截屏后端），然后抓取全屏或区域画面，得到 BGR 图像数组，供后续脚本步骤使用。

**优先级理由**：截屏是感知基础；没有它，后续视觉能力无法工作。

**独立测试**：用有效资源目录构造引擎（可 mock/真实截屏后端）；调用全屏与区域 grab；释放后端；验证帧为预期形状的 BGR 数组。

**验收场景**：

1. **给定**可写资源目录路径且所选截屏后端可用，**当**作者以该后端构造 `NGE2`，**则**构造成功，且仅该实例上可访问 `engine.capture`。
2. **给定**所选截屏后端无法创建，**当**尝试构造，**则**立即失败并给出明确错误，且不回退到另一后端。
3. **给定**已构造引擎，**当**作者无区域调用 grab，**则**返回第一块显示器的 BGR 全屏帧。
4. **给定**已构造引擎，**当**作者以屏幕物理像素区域调用 grab，**则**返回该区域的 BGR 裁剪。
5. **给定**已构造引擎，**当**作者对 capture 调用 release，**则**截屏后端被释放；同一引擎上后续 `grab()` **必须**重建同一后端并成功截屏。

---

### 用户故事 2 - 通过硬件 HID 控制键鼠（优先级：P1）

脚本作者通过引擎连接 ESP32-S3 HID 设备（串口自动发现），执行移动、点击与按键。开启拟人化时移动走拟人路径；关闭时瞬时移动。

**优先级理由**：HID 输入投递是本 MVP 的核心执行价值。

**独立测试**：真机或 mock 串口下演练 move、带 hold 的左右键点击、左右键按下/抬起、move-and-click、key down/up/click（含修饰键）；验证构造时无设备则失败。

**验收场景**：

1. **给定**可发现的 ESP32-S3，**当**作者以 `control_mode=2`（默认）构造，**则**自动发现串口并构造成功。
2. **给定**无匹配 HID 串口设备，**当**以 `control_mode=2` 构造，**则**构造失败并给出明确错误。
3. **给定**已有引擎占用 HID 串口，**当**再以 `control_mode=2` 构造第二个 `NGE2`，**则**立即失败并给出端口/设备忙的明确可操作错误。
4. **给定** `humanize=True` 的引擎，**当**作者带 duration/spread 移动，**则**指针沿拟人路径移动，且 spread > 0 时落点在散布圆盘内。
5. **给定** `humanize=False` 的引擎，**当**作者传入 duration/spread 移动，**则**瞬时跳转，duration/spread 不生效。
6. **给定**已构造引擎，**当**作者在当前位置左右键点击（可选 hold），**则**在当前指针位置发出点击，时长为指定或默认 hold。
7. **给定**已构造引擎，**当**作者在当前位置调用左右键按下/抬起，**则**对应鼠标键被按下或抬起，且不会自动配对抬起/按下（由调用方负责配对）；与完整点击 API 相区分。
8. **给定**已构造引擎，**当**作者对目标调用 move-and-click，**则**先按拟人规则移动再点击。
9. **给定**已构造引擎，**当**作者使用友好键名与修饰键调用 key_click / key_down / key_up，**则**设备收到对应 HID 动作；key_click 为 down→up 并含间隔。

---

### 用户故事 3 - 绑定窗口并使用客户区相对坐标（优先级：P2）

脚本作者在构造时传入窗口句柄。随后的移动等相关坐标按窗口客户区（物理像素）解释。可通过 window 模块查询绑定句柄、标题与客户区可视化区域。

**优先级理由**：相对窗口的脚本是常见需求，且依赖 DPI aware 物理像素。

**独立测试**：用已知 hwnd（或单测中假窗口度量）验证相对→屏幕换算与窗口查询 API。

**验收场景**：

1. **给定**有效 hwnd，**当**构造引擎，**则**进程被声明为 DPI aware，坐标使用物理像素。
2. **给定**已绑定 hwnd，**当**作者移动到 `(x, y)`，**则**目标按客户区相对坐标，经客户区矩形 + ClientToScreen 换算到屏幕。
3. **给定**已绑定 hwnd，**当**作者查询 window API，**则**得到 hwnd、标题与客户区几何（文档约定的客户区/屏幕矩形）。
4. **给定**无 hwnd，**当**作者移动到 `(x, y)`，**则**坐标为屏幕绝对物理像素。

---

### 用户故事 4 - 日志与拒绝未实现的键鼠模式（优先级：P3）

脚本作者依赖包日志（控制台 + 文件，级别由 `NGE_LOG_LEVEL` 控制）；请求本版本未实现的前台/后台键鼠模式时立即失败。

**优先级理由**：可运维性与诚实的 API 边界，避免静默误用。

**独立测试**：以 mode 0/1 构造应失败；开启文件日志并验证根名为 `nge` 的日志。

**验收场景**：

1. **给定**任意资源目录，**当**以 `control_mode` 0 或 1 构造，**则**立即失败并说明未实现（API 预留）。
2. **给定**已构造引擎，**当**产生日志，**则**控制台与日志文件均有记录，logger 层级根名为 `nge`，级别由 `NGE_LOG_LEVEL` 控制。
3. **给定**以上下文管理器使用或调用 `close()` 的引擎，**当**退出 `with` 块或 `close()` 返回，**则**本实例的 HID 串口连接与截屏后端被释放。

---

### 边界情况

- 同一进程多个 `NGE2` 实例各自拥有独立 capture，不共享截屏状态。
- 若一实例已占用 HID 串口，另一 `NGE2` 以 `control_mode=2` 构造时**必须**立即失败，并给出端口/设备忙的明确可操作错误。
- 截屏**始终**使用**第一块显示器**，即使绑定窗口在副屏（接受限制；相对客户区可能与截图不对齐）。
- 无效或已销毁的 hwnd：构造或后续坐标换算失败并给出明确错误。
- 构造时所选截屏后端不可用：立即失败；不静默回退到另一后端。
- 未知键名：在发送前解析失败时明确报错，不发送残缺 HID 流量。
- 调用 `find` 模块 API 抛出 `NotImplementedError`（仅空壳）。
- 调用 `ocr` 或 `yolo` 能力 API 抛出 `NotImplementedError`（MVP 可 import 空壳；完整行为延后）。
- release 后再 grab：`grab()` **必须**重新初始化同一后端并成功。
- `close()`（或退出 `with`）之后，再使用该引擎的 capture/control **必须**明确失败；需新建 `NGE2` 实例。
- 若 `close()` 时仍有鼠标键处于按下状态，设备侧 STOP **必须**释放按住的按键；正常脚本中调用方仍**应当**成对使用 down/up。

## 需求 *(必填)*

### 功能需求

- **FR-001**：展示名为 “Nate Game Engine”；PyPI 名为 `nate-game-engine`；import 包名**必须**为 `nge2`。
- **FR-002**：主入口**必须**为实例 API：`engine = nge2.NGE2(...)`；模块访问为 `engine.<module>.…`。**必须**支持多个独立实例。`NGE2` **必须**提供 `close()`，并**必须**支持作为上下文管理器（`with`）；关闭时**必须**释放该实例的 HID 连接（mode 2）与截屏后端。
- **FR-003**：`NGE2` 构造**必须**接受：`capture`（`"dxcam"` | `"mss"`，默认 `"dxcam"`）、`hwnd`（默认 `None`）、`humanize`（`bool`，默认 `True`）、`control_mode`（`int`，默认 `2`）、`resource_dir`（必填；相对路径相对进程 cwd；无强制子目录约定）。若所选截屏后端无法创建，构造**必须**立即失败并给出明确错误，且**不得**自动回退到另一后端。
- **FR-004**：构造**必须**声明进程 DPI aware；本功能中所有坐标为物理像素。
- **FR-005**：`control_mode` 为 `0` 或 `1` 时，构造**必须**立即失败（未实现，API 预留）。为 `2` 时**必须**自动发现 ESP32-S3 串口，找不到则构造失败。若同一进程中另一 `NGE2` 实例已占用该串口，后续以 `control_mode=2` 构造**必须**立即失败，并给出端口/设备忙的明确可操作错误。
- **FR-006**：每个 `NGE2` 实例**必须**拥有自己的 `capture` 生命周期（非进程全局单例）。
- **FR-007**：`capture` **必须**支持抓取第一屏全屏与可选区域；返回 BGR 图像数组。区域坐标**必须**为屏幕物理像素。**必须**提供释放后端操作。release 之后，同一引擎上后续 `grab()` **必须**重建同一后端并成功。
- **FR-008**：本功能 `control` **必须**仅实现硬件 HID（ESP32-S3）：移动、当前位置左右键点击（含 hold，省略时用默认）、当前位置左右键按下与抬起（不自动配对，区别于完整点击）、move-and-click、key_click（down→up 与间隔，支持修饰键）、key_down、key_up。友好键名到 HID Usage ID 的映射**必须**与既有 nge 工具包 keymap 契约等价。按下/抬起**必须**使用 HID `BTN` 行命令；完整点击可继续使用 `CLK`。
- **FR-009**：`humanize=True` 时移动**必须**使用内部拟人路径（`geom` 仅内部）。`move` 及接受 `spread` 的相关移动 API（如 `drag`、`move_and_click`）的默认 `spread` **必须**为 `10.0`（像素）。`double_click` 除外，**不得**做落点散布。`humanize=False` 时**必须**瞬时移动并忽略 duration/spread。
- **FR-010**：有 `hwnd` 时移动/点击目标**必须**为客户区相对坐标，换算使用 Win32 客户区 + ClientToScreen；无 `hwnd` 时为屏幕绝对坐标。
- **FR-011**：`window` **必须**提供绑定 hwnd（若有）、标题与客户区可视化区域。
- **FR-012**：`log` **必须**支持控制台与文件日志，根名 `nge`，级别由环境变量 `NGE_LOG_LEVEL` 控制。*（文件目录布局、`log_dir` 构造参数、ERROR 截图、日志行不含模块名等，在实现 `003-logging-layout` 后以该功能规格为准。）*
- **FR-013**：`geom` **不得**作为稳定对外脚本表面；仅服务 `control` 拟人路径。
- **FR-014**：`find` **必须**作为公开空壳，使用时抛出 `NotImplementedError`。*（找图/找色行为在实现 `004-find-vision` 后以该功能规格为准。）*
- **FR-015**：OCR/YOLO 的**识别/检测行为**不在本 MVP 范围（延后）。已安装包仍**必须**暴露可 import 的 `ocr`、`yolo` 空壳模块；调用其能力 API 时**必须**抛出 `NotImplementedError`。空壳可导入与显式错误之外，不作为 MVP 功能验收。*（识别/检测行为在实现 `005-ocr-yolo-onnx` 后以该功能规格为准。）*
- **FR-016**：默认安装**必须**为全量（MVP 支持模块的运行时依赖在基础依赖集），遵循宪章 v1.2.0。
- **FR-017**：自动化 CI **必须**覆盖纯逻辑并 mock 串口与截屏；真机与真屏为手工/可选。

### 关键实体

- **引擎（`NGE2`）**：每实例配置与模块门面；在 mode 2 下拥有 capture 与 HID 连接生命周期；支持 `close()` 与上下文管理器关闭。
- **截屏会话**：绑定到一个引擎的后端（`dxcam` 或 `mss`）；产出 BGR 帧。
- **HID 连接**：到 ESP32-S3 固件的串口链路（既有行协议）。
- **窗口绑定**：可选 hwnd 及用于坐标映射的客户区几何。
- **拟人路径**：开启 humanize 时为一次移动生成的带延迟路点序列。

## 成功标准 *(必填)*

### 可度量结果

- **SC-001**：脚本作者能在典型 Windows 桌面上于 5 秒内（不含首次装依赖）用资源目录构造引擎并取得 BGR 全屏帧。
- **SC-002**：有 ESP32-S3 时默认 control mode 构造成功率为可复现成功；无设备时构造 100% 失败并给出可操作错误。
- **SC-003**：作者可按文档样例完成 move → left_click → key_click（需要时含 left_down / left_up），无需改包内部。
- **SC-004**：绑定 hwnd 时，在 100%/125%/150% 缩放下客户区相对移动落在预期客户区内（物理像素正确）。
- **SC-005**：以 control_mode 0 或 1 构造时，在 HID/截屏副作用（DPI 声明除外）之前即失败。
- **SC-006**：CI 纯逻辑套件（mock I/O）在无物理设备、无交互桌面会话下通过。

## 假设

- 点击省略 hold 时，默认行为对齐既有工具包：约 45–110 ms 的随机拟人按下时长，除非显式传入 hold（秒）。
- 鼠标按下/抬起 API 不移动指针，仅作用于当前指针位置（与 left_click / right_click 相同）。
- key_click 间隔使用与既有工具包一致的短拟人延迟（数十毫秒量级）。
- 默认日志文件位于进程 cwd（如 `nge.log`），除非通过文档化的 logger 辅助另行设置。*（由 `003-logging-layout` 取代：默认 `{cwd}/logs/{日期}/nge-NNN.log`。）*
- `grab(region=...)` **始终**使用**屏幕**物理像素，即使绑定了 hwnd。
- 副屏窗口与第一屏截图不对齐，为本功能接受的产品限制。
- 前台/后台键鼠模式仅 API 预留；MVP 只需构造期拒绝，不实现 pywinauto。
- `nate-gaming-engine` 旧实现仅作行为契约参考（HID 协议、keymap、拟人），不作为依赖引入。
- 实现本功能时将骨架从 `nate_game_engine` 重建为 `nge2` 及八个命名模块（`capture`、`control`、`ocr`、`yolo`、`find`、`log`、`geom`、`window`）；其中 `ocr`/`yolo`/`find` 在 MVP 为空壳。

## 非范围

- OCR（RapidOCR）与 YOLO 检测**行为**（后续规格）；MVP 仍提供可 import 空壳。
- 找图/找色实现（仅空壳）。*（由 `004-find-vision` 取代。）*
- 前台与后台键鼠后端（pywinauto）。
- 除「第一块显示器」以外的多显示器截屏选择。
- 非 Windows 平台。
